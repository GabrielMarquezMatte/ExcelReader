Reads a sheet of any format across several threads: ParseAsync yields typed rows in source order, ForEachAsync hands each row to a callback on the worker threads, and AggregateAsync folds rows into one accumulator per partition.

Remarks

The caller owns the workbook and keeps it open until the returned task completes or the enumeration ends. The CSV dialect is the CsvReaderOptions the workbook was opened with.

A read falls back to one sequential pass, with the same results and no error, when DegreeOfParallelism is 1, the sheet is too small to partition usefully, the sheet is an XLS sheet or a table view, or a CSV cannot be partitioned (a stream that is not a file or a non-UTF-8 encoding).

Delivery guarantees. The general contract is the weaker CSV one: ForEachAsync is at-least-once, and a partition whose start was guessed wrongly is discarded and read again. XLSB delivers every row exactly once, in ForEachAsync too. XLSX delivers exactly once for a well-formed sheet; a malformed one can make ForEachAsync deliver a row twice. ParseAsync yields the same items in the same order as the sequential ExcelParser<T> on every format, and AggregateAsync and ForEachAsync equal their own single-thread run.

Row: ParseAsync renumbers it from the count emitted at the merge; ForEachAsync and AggregateAsync report the exact row when sequential and 0 when partitioned.

Remarks

body runs concurrently on worker threads and must be safe to call from several at once; the caller owns any synchronization. Records arrive in no particular order.

Delivery is at least once in general: body may be invoked more than once for the same record. On CSV, a partition whose start was guessed wrongly is read again from the confirmed offset, and the discarded speculative pass may already have delivered a whole partition's worth of records, which may also be misparsed: a wrong start shifts every field boundary. An exception body throws during a discarded pass is discarded with it. A start is only guessed wrongly inside a quoted field, so a CSV in which the quote character never appears delivers every record exactly once. XLSB delivers every row exactly once. XLSX does too for a well-formed sheet; on a malformed one, workers may already have called body for rows that are then dropped, so a row can be delivered twice or be one the sequential reader would not produce.

A body with side effects must therefore be idempotent and tolerate records that do not exist. For exactly-once on any source, use AggregateAsync<TAccumulator, TRecord>(IExcelSheet, SheetParallelOptions?, CancellationToken), where the discarded partition's accumulator is thrown away, and apply the side effects once it returns.

A ReadOnlySpan<T> column points into a pooled buffer the worker reuses once body returns. Copy anything that must outlive the call.

An enumerable that yields one T per data row.

Type Parameters

T

The row model type to bind each row to.

Remarks

Parsing and type conversion run in parallel; whatever the caller does per row does not. A caller whose per-row work dominates will see little gain from raising DegreeOfParallelism. For CSV, ExcelReader.Core.Reader.Csv.CsvReaderOptions.InternStrings yields substantially less here than sequentially, since each partition keeps its own dedup cache. A partition read from a wrongly guessed start is discarded before any of its rows are yielded, but its cells have already passed through the parser's converters and property setters, which must therefore be free of side effects.

ArgumentNullException

sheet or parser is null.

ArgumentException

ArgumentOutOfRangeException

A numeric option is negative.
