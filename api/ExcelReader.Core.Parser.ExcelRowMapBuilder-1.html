Accumulates a row-to-property binding for T, fed either by the source generator (feature A) or by a hand-written IExcelRowMap<T> implementation. Mirrors, without reflection, exactly what TypeMapper<T>.Build() produces from attributes.

Remarks

A builder that uses this method exclusively produces a map with no header-row step at all — the first row is already a data row. Mixing this with Property<TValue>(string[], ExcelCellReader<TValue>, ExcelPropertySetter<T, TValue>, bool, bool)/ PropertyNullable<TValue>(string[], ExcelCellReader<TValue>, ExcelPropertySetter<T, TValue?>, bool, bool)/Converted<TValue>(string[], IExcelCellConverter<TValue>, ExcelPropertySetter<T, TValue>, bool, bool) on the same builder is not supported, since one map can't both wait for a header row and skip it.

PropertyNullable<TValue>(string[], ExcelCellReader<TValue>, ExcelPropertySetter<T, TValue?>, bool, bool)

Binds a Nullable<T> property to one or more header names, using read — one of the non-nullable built-in readers, e.g. Bool or Parsable<TValue>(in Cell, in ExcelRowContext, out TValue) — to convert the matched cell, then wraps the result in Nullable<T> before calling set. There is no nullable-returning counterpart of the built-in readers to plug into Property<TValue>(string[], ExcelCellReader<TValue>, ExcelPropertySetter<T, TValue>, bool, bool) directly, because the wrapping step is identical for every value type — this method does it once, generically.

PropertyRaw(string[], ExcelRowParser<T>, bool, bool)

Binds a header to a single already-fused read+assign delegate, instead of the separate ExcelCellReader<TValue> + ExcelPropertySetter<TModel, TValue> pair Property<TValue>(string[], ExcelCellReader<TValue>, ExcelPropertySetter<T, TValue>, bool, bool)/PropertyNullable<TValue>(string[], ExcelCellReader<TValue>, ExcelPropertySetter<T, TValue?>, bool, bool) compose internally. Every bound cell costs one indirect call instead of two (read, then set) — the source generator uses this for [ExcelSerializable] models. Prefer Property<TValue>(string[], ExcelCellReader<TValue>, ExcelPropertySetter<T, TValue>, bool, bool) for hand-written maps unless the extra call genuinely matters for your workload; it's a small, row-count-proportional cost, not a correctness concern either way.
